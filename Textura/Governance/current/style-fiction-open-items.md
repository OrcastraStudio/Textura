# Style and fiction open items

These are capability and configuration questions for future work. They do not block the implemented record workflow and do not establish any user's preferences.

| Item | Current boundary and next step |
| --- | --- |
| Aesthetic aims, samples and reference authors | Chosen per author/work; no bundled corpus, mature profile or fixed author list. |
| Formal shared-setting provider | Optional. Agree version identity, acquisition, update receipts and conflict semantics before implementing an adapter. Bibliotheca integration is disabled by default. |
| Progressive fiction review packets | Protocol defined; existing CLI does not freeze Fiction/Style or enforce progressive disclosure. Executable extensions need focused verification. |
| Supplemental review staleness | Current status checks do not certify manually attached Fiction/Style records. The host checks and records that scope explicitly. |
| Statistics engine | Protocol/template only. Languages, metrics, segmentation and dependencies depend on a concrete task. |
| Actual-work versus practice workflow | Both are available, with no universal priority. Each author chooses. |
| Paid integrations and costs | No automatic paid model connection is configured. Evaluate against concrete requirements and actual costs. |
| License and publication | MIT and OrcastraStudio attribution approved; public source and v0.1.2-rc.1 pre-release publication verified on 2026-10-26. Stable-release timing and future release decisions remain open; see [release status](release-pending.md). |

Field names and ownership conventions are implementation choices, not aesthetic preferences. Record what was actually executed and keep unresolved matters visible.
