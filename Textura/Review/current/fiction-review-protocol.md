# Fiction reading and editorial review

Status: agent-executed extension protocol. No new CLI mode, progressive reader engine or automatic Fiction/Style freeze has been implemented. Existing Review execution and fallback rules remain in [README.md](README.md).

## Select the reading condition

1. Bind the task to the actual Writing version and explicitly chosen story branch. Record language, bounded text access and extraction limits. A summary does not substitute for reading all scenes.
2. For a first reader, provide only the text prefix reached so far, neutral reading instructions and the selected reading perspective. Exclude future disclosures, setting secrets, author intent/style goals and earlier reader/editor reports. Do not expose coordinator-only filenames, titles or links that reveal these.
3. Preserve the first reaction at each boundary: expectations, questions, emotional/intellectual responses and textual basis. A small adjustable set of reader perspectives may emphasize different aspects, without being representative audience statistics.
4. For full editorial review, select the relevant whole-text, Fiction, Style and real-world Evidence records. Keep event/setting, narrator assertion, character belief and reader knowledge distinct.
5. If a reviewer has already seen excluded material, state that an unspoiled first reading was not achieved. Use a fresh context where available. Instructional isolation alone is not a security boundary.
6. Recognition and questioning first passes should be isolated as the host permits; then perform countercritique and synthesis. Apply the established disclosed sequential fallback when unavailable. Reader perspectives and the three reasoning roles are distinct dimensions, not a compulsory expensive full cross-product.

## Supplemental record ownership

Fiction and Style retain their original records. For an actual review, an agent may create a new context folder under Review/current/records/fiction-contexts/ with an ASCII context ID, frozen selected files or exact immutable references, and an actual context manifest. Preserve input version/digest, reading boundary, exclusions, privacy, preparation method, coverage and any missing files. The coordinator can retain full metadata separately from reader-visible content.

Use [the context template](fiction-review-context.template.md). It is blank protocol guidance, not a runtime command. Do not rewrite an existing native review manifest or frozen packet to add new assumptions. Bind the supplemental context to the native review run if one exists; otherwise clearly identify a protocol-only review.

Native review status checks its own manifest and draft scope only. The host must check the supplemental input versions/digests separately and state what actually ran. New input or changed reading conditions require a new context/round; old reactions remain available with their original bounds.

## Report and handoff

Keep each first reaction and editorial evaluation distinct, then synthesize supported observations, differing readings, change proposals and unresolved matters. No vote or numeric quality/confidence score substitutes for reasoning. Do not force a single answer for intentionally open fiction or treat character speech as author belief.

Candidate prose edits belong to Writing. Story/setting changes and impact tracking belong to Fiction; voice/style observations belong to Style. State records actual author decisions. Adopted changes may require targeted new review; preserve the remaining unchecked scope.

No review or real-material intake is performed merely by installing this protocol.
