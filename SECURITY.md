# Security reporting

## Current status

This source candidate has no established security support period or response-time commitment. The maintainer identity and private reporting channel remain pending. Local validation is not a comprehensive security audit.

For a GitHub-hosted repository, the owner should enable private vulnerability reporting before public publication. If the repository displays Security > Advisories > Report a vulnerability, use that private channel. Otherwise request a private contact route without posting exploit details, credentials or affected private material in a public issue. No monitored email address is supplied by this draft.

Include affected version/commit, environment, impact and a minimal synthetic reproduction. Remove author material, account names, tokens and filesystem paths that reveal personal information.

Privacy labels guide the AI host; they are not encryption or operating-system enforcement. Optional parsers are not a hostile-document sandbox. The CLI does not automatically call models or publish material.

Official setup reference: [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
